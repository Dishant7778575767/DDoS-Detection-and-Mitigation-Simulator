# SENTRIX Operations Guide

## 1. System Overview

SENTRIX is an active defensive prototype designed to detect and simulate mitigation of Distributed Denial of Service (DDoS) attacks. It pairs machine-learning flow analysis with deterministic threshold checks in a dual-signal hybrid policy engine.

### Operational Philosophy
- **Simulation by Default**: SENTRIX executes all rate-limiting and defensive actions within an isolated `simulation` mode. It **never modifies host firewall rules, kernel tables, or OS networking state**.
- **Fail-Closed Dual-Signal Decision Matrix**: Single signals (ML-only or traffic threshold-only) generate alerts; **only dual-signal consensus** can request a mitigation action.
- **Strict Authorization**: Sensitive control endpoints (thresholds, cancellations, simulations, emergency disable) require valid bearer token authentication (`API_AUTH_TOKEN`).

## 2. Environment & Service Startup

### Configuration Setup
Configure required environment variables in `.env` (or set via environment):

```ini
APP_ENV=development
MITIGATION_MODE=simulation
MODEL_PATH=models/approved_model.joblib
DATABASE_URL=sqlite:///./sentrix.db
API_AUTH_REQUIRED=true
API_AUTH_TOKEN=dev-only-change-me
```

### Starting the Backend Control Plane
From the project root using the virtual environment:

```powershell
# Activate environment
.venv\Scripts\Activate.ps1

# Start FastAPI server on port 8000
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload
```

Verify service readiness:
```powershell
curl -H "Authorization: Bearer dev-only-change-me" http://127.0.0.1:8000/api/v1/health
```

### Starting the Web Dashboard
From a separate terminal in `frontend/`:

```powershell
cd frontend
npm run dev
```
Access the dashboard at `http://localhost:3000`.

## 3. Demonstration & Traffic Generation

SENTRIX supports both synthetic bounded flow generation and replay of labeled CSV datasets. Both methods route through the identical runtime ingestion pipeline (`POST /api/v1/traffic/flows`) and carry explicit demonstration provenance tags.

### Bounded Traffic Generator (`send_test_traffic.py`)
Generates scenario-specific flow observations matching PRD Section 10.2 test fixtures:

```powershell
# Run a specific scenario (normal, burst, syn_flood, threshold_only, ml_only)
python scripts/send_test_traffic.py --scenario syn_flood --count 5 --target-ip 192.168.1.150

# Run all test scenarios in sequence
python scripts/send_test_traffic.py --scenario all
```

*All flows generated by this tool are tagged with `source_id: demo-generator:<scenario>:<index>`.*

### Dataset Replay Tool (`replay_dataset.py`)
Replays pre-recorded network flow vectors from processed CIC-DDoS2019 partitions:

```powershell
# Replay 20 rows with 0.2s inter-flow delay
python scripts/replay_dataset.py --file data/fixtures/sample_test.csv --limit 20 --delay 0.2
```

*All flows replayed by this tool are tagged with `source_id: demo-replay:<file>:<row_id>`.*

## 4. Policy & Threshold Management

SENTRIX combines traffic volume thresholds with machine-learning threat probabilities.

### Active Threshold Configuration
Thresholds can be inspected and tuned via `GET /api/v1/config/thresholds` and `PATCH /api/v1/config/thresholds` or through the **Settings** view in the web UI:

- `pps_threshold`: Forward packets per second limit (default: 5,000 pps).
- `bps_threshold`: Flow byte rate limit (default: 10,000,000 bytes/s).
- `syn_pps_threshold`: SYN packet rate limit (default: 500 pps).
- `syn_ack_ratio_threshold`: Ratio of SYN to ACK flags (default: 5.0).
- `rf_probability_threshold`: Random Forest malicious probability cutoff (default: 0.75).
- `iforest_score_threshold`: Isolation Forest anomaly threshold (default: 0.2664).

### The Dual-Signal Decision Matrix

| ML Signal | Traffic Threshold | Policy Decision | System Response |
| :---: | :---: | :---: | :--- |
| **Normal** (< 0.75) | **Within Limits** | `monitor` | Normal operation. Telemetry recorded in sliding window. |
| **Normal** (< 0.75) | **Exceeded** | `alert` | Single-signal alert created; mitigation **withheld**. |
| **Suspicious** (≥ 0.75) | **Within Limits** | `alert` | Single-signal alert created; mitigation **withheld**. |
| **Suspicious** (≥ 0.75) | **Exceeded** | `request_mitigation` | Eligible for bounded rate limiting via Safety Gate. |

## 5. Mitigation Lifecycle & Safety Controls

### Safety Gate Enforcements
Before any mitigation is simulated, the fail-closed Safety Gate enforces:
1. **Allowlist / Protected Targets**: Mitigation requests targeting local loopback (`127.0.0.1`, `::1`), infrastructure DNS (`8.8.8.8`, `1.1.1.1`), or gateway subnets (`192.168.1.1`, `10.0.0.1`) are immediately rejected.
2. **Operational Bounds**: Rate limits are bounded between 100 pps and 50,000 pps; durations are bounded between 10s and 300s.
3. **Concurrency Caps**: Maximum 100 concurrent active mitigations.
4. **Flapping Cooldown**: Alerts for the same target IP are throttled by a 30-second cooldown window.

### Emergency Disable Switch
To instantly halt all ongoing mitigations and block any new requests:

```powershell
# Activate Emergency Disable
curl -X POST -H "Authorization: Bearer dev-only-change-me" http://127.0.0.1:8000/api/v1/mitigations/disable

# Clear Emergency Disable to resume normal operation
curl -X POST -H "Authorization: Bearer dev-only-change-me" "http://127.0.0.1:8000/api/v1/mitigations/disable?enable=true"
```
*Operators can also toggle Emergency Disable directly from the Mitigation Control Room in the UI.*

### Manual Mitigation Cancellation
An active simulated mitigation can be cancelled at any time by its action ID:

```powershell
curl -X POST -H "Authorization: Bearer dev-only-change-me" http://127.0.0.1:8000/api/v1/mitigations/<ACTION_ID>/cancel
```

## 6. Audit Trail & Verification

All operations, security decisions, and state machine transitions are permanently logged into the `audit_events` table.

- **Viewing Audit Logs**: Access `GET /api/v1/audit?limit=50&offset=0`.
- **Exporting CSV**: Query `GET /api/v1/audit?format=csv` or click the **Export CSV** button in the History dashboard view.
- **Integrity**: Audit records are append-only and cannot be modified or deleted through the API.

## 7. Linux Lab Probe Collector & Enforcement Operations

SENTRIX includes a lightweight real-time telemetry collector script (`collector/lab_collector.py`) and an optional, strictly bounded Linux Lab Enforcement subsystem for isolated validation.

### Collector Operation (`collector/lab_collector.py`)
The collector polls interface statistics (via Linux `/proc/net/dev` or an adaptive platform probe fallback), computes sliding-window rates (PPS, BPS, flags), and streams standardized telemetry batches directly into the ingestion endpoint (`POST /api/v1/traffic/flows`).

```powershell
# Run 5 test iterations against localhost backend
python collector/lab_collector.py --iterations 5

# Continuous collector monitoring targeting lab interface 'sentrix0'
python collector/lab_collector.py --interface sentrix0 --api-url http://127.0.0.1:8000 --interval 2.0 --target-ip 10.200.0.50
```

#### Collector Runtime Modes:
- **Live Interface Mode**: When run on Linux with access to `/proc/net/dev` and the target interface (e.g. `sentrix0`), real packet and byte deltas are sampled per window interval.
- **Fallback Probe Mode**: When run on Windows or in environments without `/proc/net/dev`, the collector automatically runs in fallback probe mode, streaming Schema 1.0.0 compliant telemetry with synthetic packet variance to validate live ingestion without crashing.

### Isolated Linux Lab Enforcement Mode
In production simulation mode (`MITIGATION_MODE=simulation`), SENTRIX performs zero OS mutations. In authorized Linux lab environments (`MITIGATION_MODE=linux_lab`):
- All rate-limiting rules are strictly confined to dedicated table `sentrix_lab` on interface `sentrix0` and subnet `10.200.0.0/24`.
- Host networking, default gateways, and loopback are hardware/kernel isolated.
- Requires formal signed authorization in `enforcement/approval.json`.
- TTL reconciliation (`app.mitigation.reconcile`) runs continuously to detect and safely clean up orphaned or expired nftables rules.
